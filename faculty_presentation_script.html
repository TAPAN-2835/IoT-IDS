Dataset & Leakage Prevention Strategy

0:45 – 1:30 (45 sec)
What to Say (Word-for-Word)

"We selected the Edge-IIoTset benchmark dataset. Unlike older simulated datasets like KDD99, Edge-IIoTset was captured from physical IoT testbeds containing real sensors, smart switches, and digital controllers across 15 attack vectors including DDoS, Ransomware, SQL Injection, and MQTT flooding.

A crucial methodological contribution of our work is Strict Data Leakage Prevention: We explicitly removed all IP addresses, MAC addresses, port numbers, and timestamps. In many existing papers, models accidentally memorize 'attacks come from IP 192.168.1.5'—yielding 99% accuracy in the lab but 0% in production. By removing identifiers, our model is forced to learn genuine packet payload structures and protocol anomalies."

Edge-IIoTset (15 Attacks) Zero Metadata Leakage Realistic Generalization

Proposed Architecture: Why CNN-GRU?

1:30 – 2:30 (60 sec)
What to Say (Word-for-Word)

"We systematically experimented with 5 architectures to find the optimal trade-off between size and accuracy:

1. Random Forest baseline: Achieved 100% binary accuracy, but produced a 12 GB model file. This is impossible to load into a 512 MB IoT gateway.
2. 1D-CNN: Captures spatial correlations within packet headers (size: 0.18 MB).
3. GRU: Captures temporal dependencies across sequential packets (size: 0.13 MB).
4. Proposed Hybrid CNN-GRU: The 1D-CNN acts as a feature extractor and dimensionality reducer. It passes compact feature maps to a lightweight GRU unit.

Because the CNN compresses the input first, the GRU requires far fewer hidden units. The result: only 21,985 parameters and a disk footprint of just 0.086 MB (86 Kilobytes)—a 54% parameter reduction compared to CNN alone, with zero loss in detection accuracy."

86 KB Model Size 21,985 Parameters Edge-Deployable

Faculty Q&A Defense Simulator
Anticipated Questions
Q1: "Why build a complex Deep Learning model when Random Forest already achieved 100% accuracy?"
Winning Answer to Deliver

"Sir/Ma'am, while Random Forest achieved 100% in binary classification, it required storing thousands of deep decision trees, resulting in a 12.0 GB model file. In an IoT deployment (e.g., smart gateways with 512 MB to 1 GB RAM), loading a 12 GB file causes immediate out-of-memory crashes. Our CNN-GRU model achieves the exact same 100% detection rate in only 0.086 MB (86 Kilobytes)—over 140,000 times smaller, making on-device, real-time edge execution feasible."

Do NOT say: "Deep Learning is newer and cooler than Random Forest." Always frame your answer in terms of memory, parameter efficiency, and hardware constraints.
Q2: "Why does your Macro-F1 drop to 0.64 in Multiclass while Overall Accuracy is 94.7%?"
Winning Answer to Deliver

"That is a great observation. Overall Accuracy is driven by majority classes like DDoS and normal traffic. However, Edge-IIoTset is inherently imbalanced—rare attack classes like XSS or Fingerprinting have fewer than a few hundred samples out of millions. Macro-F1 assigns equal weight to every class regardless of size, so errors on rare classes penalize Macro-F1 heavily. We have transparently documented this phenomenon and are implementing Focal Loss and SMOTE in Phase 5 to re-balance minority class detection."

Do NOT say: "Our model had a bug on multiclass." Frame it as an authentic data property that you understand and have an actionable plan to resolve.
Q3: "How does SHAP work in simple terms, and what did it prove in your project?"
Winning Answer to Deliver

"SHAP is based on Shapley values from cooperative game theory. Imagine all 61 packet features are players in a game collaborating to predict 'Attack'. SHAP systematically evaluates the outcome with and without each feature to determine each feature's exact contribution.

In our project, when we ran SHAP independently across CNN, GRU, and Hybrid models, all three models converged on MQTT protocol fields (mqtt.topic, mqtt.protoname) as the #1 decision driver. This proves that our model isn't learning spurious noise—it is detecting genuine protocol tampering in IoT communications."

Q4: "What is your data leakage policy, and why does it matter?"
Winning Answer to Deliver

"Data leakage occurs when training data contains features that won't be valid predictors in real-world deployment. In IoT datasets, attackers and victims have fixed IP addresses during recording. If IP and port numbers remain in the dataset, the neural network simply memorizes that 'Traffic from 192.168.1.5 = Attack'.

We enforced a strict drop policy for all IP, MAC, port, and timestamp fields. This forces the model to evaluate only the structural telemetry and protocol headers, guaranteeing realistic generalization on unseen networks."

Q5: "Where will this system actually sit in an IoT network?"
Winning Answer to Deliver

"Our lightweight model (86 KB) is designed to run inline on the IoT Gateway or Local Edge Broker (such as an industrial Raspberry Pi running Mosquitto MQTT). As smart sensors transmit data to the gateway, the hybrid model inspects packet headers with sub-millisecond inference time. If an attack is detected, an alert and a SHAP explanation are logged immediately to the local security dashboard without requiring cloud round-trips."
