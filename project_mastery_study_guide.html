1. Core Project Flow & The 3 Pillars

High-Level Pipeline Flow

Raw Edge-IIoTset Data (61 features, 15 attacks) ➔ Zero-Leakage Filter (Drop IP, MAC, Ports, Time) ➔ Benchmark Pipeline (RF, 1D-CNN, GRU, CNN-GRU) ➔ Flagship CNN-GRU (21K params, 86 KB) ➔ SHAP XAI Engine (Game-Theoretic MQTT Attribution) ➔ Real-Time Gateway Alert.

Pillar 1: Edge Feasibility

Downsized model footprint to 86 KB (54% smaller than CNN alone, 140,000x smaller than Random Forest), allowing it to fit into IoT gateway cache.

Pillar 2: Zero Leakage

Stripped all static identifiers (IPs, Ports, Timestamps) to guarantee the AI learns genuine protocol anomalies rather than memorizing IP addresses.

Pillar 3: Explainability

Applied game-theoretic SHAP across all models, proving mathematically that MQTT protocol fields drive intrusion detection.

4. IoT Real-World Deployment Architecture

Individual sensors (smart meters, bulbs, temperature probes) do not run the AI. The model is saved on the IoT Edge Gateway / Local MQTT Broker (e.g., Raspberry Pi).

The 5-Step Real-Time Execution Lifecycle

1. Packet Ingestion: Sensor transmits an MQTT telemetry message.
2. Header Sniffing: Gateway intercepts packet headers via libpcap/Scapy and extracts 61 features (< 0.5 ms).
3. AI Inference: Gateway passes features to best_model.pt (< 10 ms).
4. Inline Action: If Normal ➔ Forward packet. If Attack ➔ Drop packet immediately and isolate the compromised sensor.
5. Explainable Alert: Gateway logs the SHAP explanation (e.g., *"Abnormal MQTT Topic Length"*) to the admin dashboard.

8. Tough Faculty Defense Q&A

Q1: Why not just use Random Forest if it got 100%?
"Random Forest required 12.0 GB of storage, causing instant out-of-memory crashes on IoT gateways. Our CNN-GRU model achieves the same 100% accuracy in 86 KB (140,000x smaller), enabling real-time on-device execution."
Q2: Why is Macro-F1 0.64 in multiclass when accuracy is 94.7%?
"Edge-IIoTset is heavily imbalanced. Rare attacks like XSS have few samples. Macro-F1 treats all 15 classes equally, honestly showing rare-class difficulty. We are implementing Focal Loss in Phase 5 to resolve this."
Q3: Where does this model sit in an IoT network?
"On the IoT Edge Gateway or Local MQTT Broker (like a Raspberry Pi). It inspects packet headers inline in under 10 ms and drops malicious packets locally without needing cloud round-trips."
